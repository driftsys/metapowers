**Brief contents**
- **Goal:** find why CI failed in `ci.log` and report the root cause. Don't fix anything.
- **Constraints:** read-only. No file edits, no git writes, no re-running CI.
- **Scope:** read `ci.log` in full, or in sections if it is large. Locate the first real failure, not the later cascade errors. Name the failing job, step, test or command, and quote the key error lines with line numbers.
- **Separate:** root cause, secondary or cascading failures, and noise such as warnings and retries.
- **Flags:** whether the failure looks like a code defect, a flaky test, an environment or dependency problem, or a config problem.
- **Output:** a summary under about 200 words, with the cause stated first, then evidence with `ci.log:<line>` references and a confidence level. If the cause is unclear, it should list what is missing instead of guessing.
