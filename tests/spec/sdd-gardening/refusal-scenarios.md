## Interface 2 — Return + refusal (clean-room subagent loaded with `AGENT.md` + a fixture)

Harness: spawn a clean-room subagent whose instructions are the verbatim body of
`skills/sdd-gardening/AGENT.md`, then point it at a fixture. R1–R5 use a fixture
under [fixtures/refusal/](fixtures/refusal/): the subagent **inspects** (reads the
spec/plan, runs the tests read-only) and emits its **return digest** — it does
not mutate files or run git-writes, so it stays isolated from the metapowers
repo. The R3-final run is the exception: it wrote a record and the observer
checked `git diff` on `0001-retry-policy.md`. R6–R9 use a throwaway sandbox built by
[setup-sandbox.sh](setup-sandbox.sh) (`project-layout` or `project-layout-ids`,
with the sandbox's `.claude/` removed, so the repository's own rules are not
loaded; user-level rules still were, as the results records note): the subagent
**writes** the records and runs the `git mv` archive in that sandbox, and the
observer records `git status --short`, a search of the new records, and the
digest's `records:` and `wip:` fields. The R6, R7 and R3-final runs therefore
also assert the result of the `git mv` archive and the record writes. The
live dev-role runs (P3/K2b/K3) cover the archive mechanics in the default
layout; this battery tests the **return + refusal decision** and, in R6-R9, the
file-naming and archive layout.
