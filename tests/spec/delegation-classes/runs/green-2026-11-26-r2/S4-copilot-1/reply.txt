`validate_session(token)` in `src/auth/session.py` does a plain lookup:

1. It calls `SESSIONS.get(token)`, which reads from the in-memory dict that `create_session` fills.
2. If the token isn't in the dict, it returns `None`.
3. If the token is found, it returns the stored `user_id`.

Gaps worth knowing about:
- **No expiry:** sessions store a `created` timestamp, but `validate_session` never checks it. A session stays valid until the process restarts.
- **No revocation:** there is no logout or delete function.
- **In-memory only:** sessions are lost on restart and aren't shared across processes.
- **Timing-safe comparison:** the dict lookup doesn't use one, though this matters little with 128-bit random tokens.

Tokens come from `secrets.token_hex(16)`, so they are cryptographically random.
