`validate_session(token)` in `src/auth/session.py` does a plain dictionary lookup:

1. It looks up `token` in the in-memory `SESSIONS` dict.
2. If the token isn't there, it returns `None`.
3. If the token is there, it returns the session's `user_id`.

Tokens come from `create_session`. That function generates them with `secrets.token_hex(16)` and stores `{"user_id", "created"}` under each one.

Weaknesses:
- **No expiry:** `created` is recorded but never checked, so sessions never time out.
- **No revocation:** there is no logout or invalidation function.
- **In-memory storage:** sessions are lost on restart and aren't shared across processes.
- **Timing:** the dict lookup isn't a constant-time comparison. This is minor, because the tokens are random.

This is authentication code, so any fix would be classed critical.
