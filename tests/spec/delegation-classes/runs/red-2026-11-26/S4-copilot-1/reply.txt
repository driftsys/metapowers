`validate_session(token)` in `src/auth/session.py` does a single check:

1. It looks up `token` in the in-memory `SESSIONS` dict, which `create_session` fills.
2. If the token isn't there, it returns `None`, meaning the session is invalid.
3. If the token is there, it returns the session's `user_id`, meaning the session is valid.

**Gaps:**
- **No expiry check:** `create_session` stores a `created` timestamp, but `validate_session` never reads it. Sessions stay valid indefinitely.
- **No cleanup or revocation:** Nothing removes entries from `SESSIONS`, so there is no logout and no expiry cleanup.
- **In-memory only:** Sessions are lost on restart and aren't shared across processes.
- **Falsy `user_id` ambiguity:** `None` is the invalid result, so callers have to handle that. A `user_id` of `0` or an empty value could be mistaken for invalid if they use truthiness checks.

Tokens come from `secrets.token_hex(16)`, so they are cryptographically random.
