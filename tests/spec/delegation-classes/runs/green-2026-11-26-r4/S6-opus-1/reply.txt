## Plan: show the user's email on the settings screen

1. **Render the email in `render_settings`** (`src/ui/settings_view.py`). Read `user.get("email")` and add a line like `<p>Email: …</p>` below the heading. If the user has no email, either leave the line out or show a placeholder like "not set". Escape the value with `html.escape` before putting it in the HTML.
   Class: standard (default: a user-facing screen that displays personal data; waiting on your privacy answer below)

2. **Escape the name the same way.** `user['name']` is currently put into the HTML without escaping. Fixing it in the same edit keeps the function consistent and closes an XSS hole next to the new field.
   Class: standard (same file and screen as step 1)

3. **Add tests** in a new `tests/test_settings_view.py`. Check three cases: an email is shown, a missing email doesn't raise an error, and a name or email containing `<script>` comes out escaped.
   Class: standard (tests take the class of the code they test)
